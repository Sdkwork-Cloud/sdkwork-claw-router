# SdkWork Claw Router v0.2.0

Release date: 2026-05-16

## Scope

This release record covers the capability slice developed after the successful `v0.1.0` release. The main change is configurable Claw Router authentication runtime behavior across the admin API, app API, portal runtime, OpenAPI contracts, and generated SDKs.

No failed GitHub release exists after `v0.1.0`, so this release does not need to merge unpublished release notes from a previously failed tag. The change log was reconstructed from the current working tree against the last successful release tag `v0.1.0`.

## Delivered

- Added admin-managed authentication settings for Claw Router, including login methods, QR login, OAuth visibility, recovery methods, registration methods, and verification policy flags.
- Added product-domain ports and SQL stores for admin auth settings, with SQLite and PostgreSQL implementations wired through the product infrastructure module registry.
- Added app runtime auth settings retrieval so the portal login experience can read the active tenant or organization policy instead of using a hard-coded auth method matrix.
- Added policy enforcement for password, email code, phone code, QR, session bridge, recovery, and registration verification flows.
- Preserved the stricter default auth posture: password login remains enabled by default while QR, code login, OAuth, and session bridge require explicit settings.
- Updated the portal auth routes to consume runtime auth config through the shared generated SDK surface rather than a static local configuration.
- Added an admin auth settings page and routing so operators can manage authentication UI and policy behavior from the portal.
- Updated OpenAPI outputs, API contract manifests, schema registries, frontend operation manifests, and generated TypeScript SDK types for the new auth settings endpoints and payloads.
- Adjusted app session and app auth tests so bridge, QR, code login, and registration verification cases explicitly opt into the runtime policy they are validating.
- Clarified installer CLI test setup so SQLite installer scenarios declare the desktop deployment profile explicitly.
- Added final platform-native release installers for service and desktop package modes: Linux `.deb` packages for Ubuntu/Debian `apt install`, Windows `.msi` packages through WiX, and macOS `.pkg` packages through `pkgbuild`.
- Updated GitHub release packaging so `archive` and `container` remain portable packages while `service` and `desktop` upload native installers instead of only `.tar.gz` or `.zip` archives.
- Changed server/service release package defaults to local SQLite so a single node can start without manual database preparation.
- Updated Linux `.deb` service behavior to create `/etc/default/clawrouter`, generate the default runtime TOML, and run `clawrouterctl ensure` plus `refresh-catalog --force` automatically from systemd before starting the gateway.
- Simplified Ubuntu/Debian installation documentation to `apt install`, `systemctl enable --now`, then health checks, while keeping PostgreSQL configuration documented for production and multi-node deployments.
